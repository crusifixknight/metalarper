# Metalarper — фронтенд каталога игр

Next.js 16 (App Router, Cache Components) + Tailwind CSS 4. Данные приходят из
Django REST API, который лежит в соседней папке `../backend`.

Сайт показывает каталог игр с фильтрами, поиском и сортировкой, позволяет
войти или зарегистрироваться через панель в шапке и открывает страницу игры
со Steam-метаданными, связанными и похожими играми.

## Запуск

### 1. Бэкенд

```powershell
cd backend
Copy-Item .env.example .env   # и заполните SECRET_KEY
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

API будет доступно на `http://127.0.0.1:8000/api/games/` (12 игр на страницу),
обложки — на `http://127.0.0.1:8000/media/...`. Steam-данные подтягиваются в
фоне; при необходимости кэш можно заполнить заранее:
`python manage.py refresh_steam`.

### 2. Фронтенд

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local   # опционально, значения по умолчанию совпадают
npm run dev
```

Каталог: `http://localhost:3000`, страница игры: `/games/<slug>`.

## Как устроена интеграция

- `lib/api.ts` — типизированный клиент: список с пагинацией и фильтрами,
  деталь по slug, справочники жанров и студий, кэш ответов на 60 секунд.
  Здесь же типы `SteamData` и `GameBrief` и поля `age_rating`, `steam`,
  `related_games`, `recommended_games`.
- `app/layout.tsx` — корневой layout: шапка с логотипом и серверный
  `AuthStatus` внутри `<Suspense>`, чтобы остальная страница оставалась
  статической.
- `app/page.tsx` — статический каркас страницы; каталог и сайдбар стримятся
  в отдельных `<Suspense>`.
- `components/CatalogFilters.tsx` — серверная часть фильтров: разбирает
  query-параметры и загружает справочники.
- `components/FilterSidebar.tsx` — GET-форма со всеми контролами; состояние
  живёт в URL, поэтому фильтры работают без клиентского JavaScript.
- `components/CatalogResults.tsx` — запрос к API с фильтрами, сортировка,
  пагинация по 12, состояния «пусто», «страницы нет», «некорректный фильтр»
  и «API недоступен».
- `components/CatalogSearch.tsx` — строка поиска в шапке: поле и кнопка-лупа
  привязаны к форме фильтров, поэтому поиск применяется вместе с ними.
- `components/GameCard.tsx` — карточка каталога из полей API (`cover`,
  `genres`, `release_year`, `developer`); Steam-метаданные в сетке намеренно
  не показываются.
- `components/GameMeta.tsx` — компактные метаданные рядом с заголовком игры:
  звёзды, возрастной рейтинг, дата последней новости Steam, текущие игроки и
  ссылка в Steam. Если данных нет, блок просто показывает меньше элементов.
- `components/StarRating.tsx` — дробный рейтинг 0–5 звёзд с доступной
  подписью для скринридеров.
- `components/GameMiniCard.tsx` — компактная карточка для секций связанных и
  похожих игр.
- `app/games/[slug]/page.tsx` — страница игры: обложка, `GameMeta`, описание,
  секции «Связанные проекты» и «Похожие игры»; `404` от API превращается
  в `notFound()`.
- `next.config.ts` — домен обложек берётся из `API_URL` для `next/image`
  (`remotePatterns` на `/media/**`).

Запросы к API выполняются только на сервере (Server Components), поэтому
`API_URL` не публикуется в браузер и настраивать CORS на бэкенде не нужно.
Обложки отдаёт `next/image`: домен бэкенда должен быть разрешён в
`next.config.ts` (уже выводится из `API_URL`).

Переменная окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `API_URL` | `http://127.0.0.1:8000` | Базовый адрес Django-бэкенда |

## Авторизация

Пользовательский сценарий: кнопка «Войти» в шапке открывает панель с формой
входа, из неё можно переключиться на регистрацию без перезагрузки страницы.
После успешного входа в шапке показываются имя пользователя и кнопка выхода.

- `components/auth/AuthStatus.tsx` — серверная часть: читает cookie сессии и
  рендерит либо пользователя с выходом, либо `AuthMenu`.
- `components/auth/AuthMenu.tsx` — клиентский popover: переключает
  `LoginForm` и `RegisterForm`, закрывается по клику вне и по `Esc`.
- `components/auth/LoginForm.tsx`, `RegisterForm.tsx` — клиентские формы на
  `useActionState`; контролируемые поля сохраняют значения после ошибки.
- `app/actions/auth.ts` — Server Actions `loginAction`, `registerAction`,
  `logoutAction`: валидируют форму, вызывают API, ставят/удаляют cookies и
  делают `revalidatePath("/", "layout")`.
- `lib/auth-api.ts` — серверный клиент `/api/auth/register/`, `/login/`,
  `/refresh/`; ошибки приходят как `AuthApiError` со статусом и пофайловыми
  сообщениями.
- `lib/auth-errors.ts` — переводит ошибки DRF на русский и собирает
  `AuthFormState` для форм.
- `lib/session.ts` — HttpOnly cookies `ml_access`, `ml_refresh`, `ml_user`:
  установка, очистка и чтение текущего пользователя.
- `proxy.ts` — прокси Next.js 16: если access-токен отсутствует или скоро
  истекает, продлевает его через `/api/auth/refresh/` до отрисовки страницы;
  если бэкенд отклонил refresh-токен, очищает сессию, а при недоступном
  бэкенде оставляет её как есть.

Токены живут только в HttpOnly cookies (`SameSite=Lax`, `Secure` в
production) и не попадают в браузерный JavaScript или `localStorage`.
Access-токен действует 30 минут, refresh — 1 день. Logout просто удаляет
cookies: blacklist/отзыв refresh-токена на бэкенде не реализованы.

## Фильтры каталога

Фильтрацию выполняет бэкенд (`api/filters.py`):

| Параметр | Значение |
| --- | --- |
| `genres` | slug жанра; можно несколько, логика «ИЛИ» |
| `developer` | slug студии |
| `year_from` / `year_to` | диапазон годов выпуска |
| `search` | поиск по названию |
| `page` | номер страницы |

Фронтенд добавляет только `sort` (`title`, `year-desc`, `year-asc`): в API нет
параметра `ordering`, поэтому для сортировки по году подгружаются все страницы
уже отфильтрованного результата, а сортировка и нарезка на страницы по 12
выполняются на сервере Next.js. Справочники для сайдбара берутся из
`/api/genres/` и `/api/developers/`, списки кэшируются в памяти процесса.

Строка поиска находится в шапке справа от заголовка «Каталог игр». Она
отправляется вместе с формой фильтров (HTML-атрибут `form`), поэтому поиск
не сбрасывает выбранные жанры, год и студию. Итоговый запрос хранится в URL
(`?search=...`), переживает перезагрузку и пагинацию.

Ограничения:

- на один запрос — не больше 500 страниц (6000 игр), иначе показывается
  понятная ошибка;
- если в URL неизвестный жанр/студия, API отвечает `400`, и каталог предлагает
  сбросить фильтры.
