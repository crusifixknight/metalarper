# Metalarper — фронтенд каталога игр

Next.js 16 (App Router, Cache Components) + Tailwind CSS 4. Данные приходят из
Django REST API, который лежит в соседней папке `../backend`.

## Запуск

### 1. Бэкенд

```powershell
cd backend
Copy-Item .env.example .env   # и заполните SECRET_KEY
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

API будет доступно на `http://127.0.0.1:8000/api/games/` (12 игр на страницу),
обложки — на `http://127.0.0.1:8000/media/...`.

### 2. Фронтенд

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local   # опционально, значения по умолчанию совпадают
npm run dev
```

Каталог: `http://localhost:3000`, карточка игры: `/games/<slug>`.

## Как устроена интеграция

- `lib/api.ts` — типизированный клиент: список с пагинацией и фильтрами,
  деталь по slug, справочники жанров и студий, кэш ответов на 60 секунд.
- `app/page.tsx` — статический каркас страницы; каталог и сайдбар стримятся
  в отдельных `<Suspense>`.
- `components/CatalogFilters.tsx` — серверная часть фильтров: разбирает
  query-параметры и загружает справочники.
- `components/FilterSidebar.tsx` — GET-форма со всеми контролами; состояние
  живёт в URL, поэтому фильтры работают без клиентского JavaScript.
- `components/CatalogResults.tsx` — запрос к API с фильтрами, сортировка,
  пагинация по 12, состояния «пусто», «страницы нет», «некорректный фильтр»
  и «API недоступен».
- `components/CatalogSearch.tsx` — строка поиска в шапке: поле и кнопка-лупа
  привязаны к форме фильтров, поэтому поиск применяется вместе с ними.
- `components/GameCard.tsx` — карточка из реальных полей API (`cover`,
  `genres`, `release_year`, `developer`).
- `app/games/[slug]/page.tsx` — детальная страница; `404` от API превращается
  в `notFound()`.
- `next.config.ts` — домен обложек берётся из `API_URL` для `next/image`.

Запросы к API выполняются только на сервере (Server Components), поэтому
`API_URL` не публикуется в браузер и настраивать CORS на бэкенде не нужно.
Обложки грузятся напрямую с бэкенда (это обычные `<img>`-запросы, CORS им не
нужен).

Переменная окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `API_URL` | `http://127.0.0.1:8000` | Базовый адрес Django-бэкенда |

## Фильтры каталога

Фильтрацию выполняет бэкенд (`api/filters.py`):

| Параметр | Значение |
| --- | --- |
| `genres` | slug жанра; можно несколько, логика «ИЛИ» |
| `developer` | slug студии |
| `year_from` / `year_to` | диапазон годов выпуска |
| `search` | поиск по названию |
| `page` | номер страницы |

Фронтенд добавляет только `sort` (`title`, `year-desc`, `year-asc`): в API нет
параметра `ordering`, поэтому для сортировки по году подгружаются все страницы
уже отфильтрованного результата, а сортировка и нарезка на страницы по 12
выполняются на сервере Next.js. Справочники для сайдбара берутся из
`/api/genres/` и `/api/developers/`, списки кэшируются в памяти процесса.

Строка поиска находится в шапке справа от заголовка «Каталог игр». Она
отправляется вместе с формой фильтров (HTML-атрибут `form`), поэтому поиск
не сбрасывает выбранные жанры, год и студию. Итоговый запрос хранится в URL
(`?search=...`), переживает перезагрузку и пагинацию.

Ограничения:

- на один запрос — не больше 500 страниц (6000 игр), иначе показывается
  понятная ошибка;
- если в URL неизвестный жанр/студия, API отвечает `400`, и каталог предлагает
  сбросить фильтры.
